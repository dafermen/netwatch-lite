User Manual

Operate NetWatch Lite with confidence

Monitor devices, manage the JSON inventory, run full checks, and interpret health states from one lightweight dashboard.

Dashboard

The dashboard shows device health grouped by facility and category. Facility and category sections stay compact so large inventories remain easy to scan.

  • Use facility buttons to focus one site, then run only that facility when hundreds of devices are configured.
  • Use Run All Facilities to execute all configured ping, TCP and HTTP/HTTPS checks immediately.
  • Use Full Check for configured ping, TCP and HTTP/HTTPS checks, or Ping Only for a fast connectivity-only run.
  • Use Run Failed when it appears to retry only devices currently marked as Degraded or Down.
  • Use Run on any device row to check only that device, including healthy devices.
  • Use Auto Refresh to run a full check using the configured interval.
  • Search configured devices before checking or after a partial run, by name, IP, hostname, facility, category or URL. Not checked is not an outage.
  • Run Group checks the selected category within the selected facility, or across all sites with All Facilities. Search filters the view only.
  • The reset icon beside search clears dashboard filters without deleting results or history. Click a facility/category header band or its arrow to expand or collapse it.
  • Configure Command beside Website URL in the device form. Dashboard Command copies the literal text for the operator to review and paste; the app never executes it.
  • Use status filters to show all devices, online devices, offline devices, or problems.

Workstation Peripherals

Use Peripherals to maintain printer/scanner manufacturer and model records for the active support group. In Configuration, choose Workstation as the device type and record printers and scanners separately as Not recorded, None or Assigned.

Assignments can include multiple models, USB/network/other connections, asset IDs and notes. Remove assignments before deleting a model. Catalog and assignments travel together when copying or exporting a profile.

This is recorded inventory, not automatic USB discovery or peripheral health. Add a network printer as a separate monitored device when ping/TCP checks are needed.

Workstations provides read-only search, facility/model and pending-inventory filters. None counts as recorded; Not recorded remains pending. Select a model name in Peripherals to find its workstations. Filter links and paging survive reload; matching unit counts are separate from workstation counts.

Status Rules

Each device receives one final status after its checks complete.

  • Healthy: every configured ping, TCP and HTTP check succeeds.
  • Degraded: at least one check succeeds, but one or more checks fail.
  • Down: no configured checks succeed.
  • In Ping Only mode, TCP ports are skipped for that execution and shown as skipped instead of failed.
  • Ping badges include diagnostic details on hover, including the ping target, ICMP status, and configured timeout.

Configuration

The Configuration page edits the active region JSON used by the backend.

  • Use Support Groups to switch between independent JSON profiles such as Support Team A, Support Team B, or Demo.
  • Search/filter the region-grouped list and use its row menu to activate, copy, rename, delete or open a profile's configuration. Selection alone does not activate it.
  • Dashboard and Configuration always use the active support group profile.
  • Devices are grouped by facility and category; both levels are collapsible by default.
  • Filter configured devices by name, address, hostname, facility, or category.
  • Add, copy, or edit name, facility, address, hostname, website URL, category, enabled state, and checks from a modal editor.
  • Manage custom classifications in Device Types. Protected system types keep existing behavior; types assigned to devices cannot be deleted. Device type guide.
  • Use Bulk Edit for spreadsheet-style updates to common fields, with one save button per row.
  • Set Auto refresh to control how often Auto Refresh runs a full check.
  • Use Ping this device by hostname when that device's IP changes but its DNS name stays stable.
  • Use Themes to create, rename, activate, delete, and color reusable GUI templates.
  • Theme naming operations save immediately; color edits remain in preview until Save Colors. Unsaved colors require confirmation before being discarded. Administration guide.
  • Use Export JSON and Import JSON to back up or restore the full configuration.
  • Click Save Settings to persist settings and create config.backup.json.

JSON File

The portable build keeps runtime JSON profiles beside NetWatch-Lite.exe, so operators can manage independent support group inventories.

  • If support group profiles are missing, NetWatch Lite creates a Support Team A profile and a protected Demo profile.
  • Reload reloads the active inventory without restarting the app.
  • Export JSON downloads the active support group configuration; Import JSON validates a selected file before replacing the active support group configuration.
  • Invalid JSON is reported in the UI/API so it can be corrected.
  • Reports separates Summary, Runs and Devices with shared historical filters, recorded-check details and private CSV/JSON downloads. Healthy evaluations is a sample ratio, not continuous uptime. Reports guide.
  • TCP checks verify whether a socket connection can be opened.
  • HTTP/HTTPS checks send an anonymous GET with a per-attempt timeout, expected status and optional case-sensitive response text. Errors and duration appear in Dashboard and Reports. Redirects are not followed and TLS certificates must be valid. HTTP check guide.

Integrations

The Integrations page stores future inbound inventory and outbound report endpoint settings in local runtime JSON.

  • Use Local JSON while the app is running without external systems.
  • Use External endpoint as the planned source mode for importing facilities, devices, and settings later.
  • Use Send Report Data to prepare the endpoint that will receive report summaries and detailed rows when outbound delivery is implemented.

Security Model

NetWatch Lite is intended for trusted internal use. It does not currently include built-in authentication, user roles, or permission-based authorization.

  • Runtime storage, backups and exports are local and ignored by Git.
  • Portable releases should include only the safe sample JSON, not active operational profiles.
  • Import JSON validates file type, size, JSON structure, and monitor configuration before replacing active data.
  • Configuration saves are validated by the backend and create local backups.
  • Deploy behind existing internal controls such as VPN, firewall rules, reverse proxy authentication, or Windows access controls when shared with other users.

About

NetWatch Lite

A lightweight, open network monitoring dashboard for small teams, labs, and practical infrastructure visibility.

Project Philosophy

NetWatch Lite is designed to be simple to run, easy to understand, and useful without requiring a database server or complex deployment.

It uses an editable JSON inventory, asynchronous checks, and a clean web interface to provide immediate visibility into device availability.

Open Project

This is intended as a free and open project that can be studied, modified, extended, and adapted to real environments.

Repository: github.com/dafermen/netwatch-lite

Good contributions include better checks, improved UI, export features, alerting, authentication, historical storage, and deployment improvements.

Technology

Built with .NET 8, ASP.NET Core Minimal API, C#, Bootstrap 5, FontAwesome, and vanilla JavaScript.

The app can be published as a portable Windows package with the .NET runtime included.

Operational Note

NetWatch Lite helps with visibility, but it is not a replacement for enterprise monitoring, incident response processes, or security controls.

Use it as a transparent, practical foundation that can grow with your needs. For shared deployments, place it behind existing internal access controls because application-level authentication and roles are future enhancements.
