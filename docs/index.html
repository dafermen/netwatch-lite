NetWatch-Lite Documentation

Documentacion tecnica y operativa del monitor de red ASP.NET Core + Bootstrap. Cubre arquitectura, JSON editable, endpoints, servicios, UI y publicacion portable para Windows.

Resumen Del Proyecto

NetWatch-Lite monitorea dispositivos desde un archivo JSON editable, ejecuta checks asincronos de ping y TCP, calcula estado agregado por dispositivo y muestra resultados en un dashboard web.

Backend

ASP.NET Core minimal API en .NET 8. Expone endpoints para leer cache, forzar ejecuciones, recargar JSON y consultar dispositivos.

Monitor

Usa Ping.SendPingAsync, TcpClient.ConnectAsync, Task.WhenAll y SemaphoreSlim para concurrencia controlada.

UI

HTML, Bootstrap 5, FontAwesome y JavaScript con fetch API. Incluye resumen, categorias, filtros, busqueda y controles de ejecucion.

Portable

Se publica como win-x64 self-contained. El archivo devices.json queda junto a NetWatch-Lite.exe para editar inventario sin recompilar.

Flujo De Ejecucion

  1. La aplicacion inicia en Program.cs.
  2. JsonDeviceRepository.ReloadAsync carga y normaliza devices.json.
  3. La UI llama GET /api/monitor/refresh para obtener resultados cacheados.
  4. Si no hay cache, MonitorExecutionService ejecuta un full check inicial.
  5. NetworkMonitorService.CheckAllDevicesAsync revisa dispositivos habilitados en paralelo.
  6. Se calcula Healthy, Degraded o Down.
  7. El backend agrupa resultados por categoria y genera metricas del dashboard.

Configuracion JSON

En desarrollo el archivo fuente vive en Data/devices.json. Al publicar portable se copia como devices.json junto al ejecutable.

{
  "settings": {
    "intervalSeconds": 15,
    "timeoutMs": 1000,
    "maxParallelChecks": 50
  },
  "devices": [
    {
      "name": "Web Server",
      "ip": "192.168.4.10",
      "category": "Servers",
      "enabled": true,
      "checks": [
        { "type": "ping" },
        { "type": "tcp", "port": 80 },
        { "type": "tcp", "port": 443 }
      ]
    }
  ]
}
CampoDescripcion
intervalSecondsIntervalo de auto refresh en la UI.
timeoutMsTimeout de ping y TCP en milisegundos.
maxParallelChecksLimite global de checks concurrentes.
categoryGrupo visual del dashboard.
enabledPermite conservar dispositivos sin monitorearlos.
checksLista de checks. Soporta ping y tcp.

Estados Y Metricas

EstadoReglaColor UI
HealthyPing exitoso y todos los puertos TCP abiertos.Verde
DegradedPing exitoso, pero al menos un puerto TCP cerrado.Amarillo
DownPing fallido.Rojo

Disponibilidad: (HealthyDevices / TotalDevices) * 100, redondeado a un decimal.

Endpoints

MetodoRutaFuncionRespuesta
GET/api/devicesObtiene dispositivos normalizados.Lista de Device.
POST/api/reloadRecarga devices.json desde disco.Conteos y settings.
GET/api/resultsCompatibilidad. Fuerza ejecucion completa.MonitorResponse.
GET/api/monitor/refreshDevuelve cache actual. Si no existe, ejecuta una vez.MonitorResponse.
POST/api/monitor/runFuerza full check sin permitir solapamiento.MonitorResponse o HTTP 409.

Servicios

ServicioMetodos ClaveEntrada / Salida
JsonDeviceRepository ReloadAsync, GetConfigurationAsync, GetDevicesAsync Lee JSON desde disco y entrega configuracion normalizada.
NetworkMonitorService CheckAllDevicesAsync, PingAsync, CheckPortAsync Entrada: configuracion actual. Salida: lista de DeviceResult.
MonitorExecutionService GetCachedResultsAsync, RunFullCheckAsync, TryRunFullCheckAsync Coordina cache, full checks y bloqueo contra ejecuciones simultaneas.

Frontend

wwwroot/index.html define el layout: cabecera, controles de ejecucion, metricas, busqueda, filtros y contenedor de resultados. El dashboard inicia en modo manual por defecto.

wwwroot/app.js contiene funciones JSDoc para:

  • Consumir /api/monitor/refresh y /api/monitor/run.
  • Renderizar metricas, categorias, filas, badges de estado y puertos.
  • Contraer y expandir grupos de categorias para navegar inventarios grandes.
  • Manejar modo manual por defecto, auto refresh ON/OFF, Refresh Now y Run Full Check.
  • Filtrar por texto, online, offline y problemas.

Build Y Ejecucion Local

dotnet restore

Crear Portable Windows

Comando recomendado:

dotnet publish NetWatch.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -o publish/win-x64-portable

Resultado esperado:

publish/win-x64-portable/
├── NetWatch-Lite.exe
├── devices.json
├── appsettings.json
├── wwwroot/
└── runtime dependencies...

Crear ZIP en macOS:

ditto -c -k --sequesterRsrc --keepParent publish/win-x64-portable publish/NetWatch-Lite-win-x64-portable.zip

Uso en Windows:

  1. Descomprimir el ZIP.
  2. Editar devices.json en la misma carpeta de NetWatch-Lite.exe.
  3. Ejecutar NetWatch-Lite.exe.
  4. Abrir la URL que muestra la consola.

Notas Operativas

  • El archivo devices.json puede recargarse desde el boton Reload JSON.
  • La aplicacion inicia en modo manual; el auto refresh solo empieza cuando el operador activa el boton.
  • Run Full Check no permite ejecuciones solapadas; si una ya corre, el backend responde HTTP 409.
  • Para redes grandes, ajustar maxParallelChecks segun capacidad de red y equipo.
  • El ping puede requerir permisos o reglas de firewall dependiendo del sistema operativo y la red.
  • Los checks TCP indican si el puerto acepta conexion, no validan el protocolo de aplicacion.
