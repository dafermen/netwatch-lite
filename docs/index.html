NetWatch Lite Documentation

Documentacion tecnica y operativa del monitor de red ASP.NET Core + Bootstrap. Cubre arquitectura, JSON editable, endpoints, servicios, UI y publicacion portable para Windows.

Resumen Del Proyecto

NetWatch Lite monitorea dispositivos desde un archivo JSON editable, ejecuta checks asincronos de ping y TCP, calcula estado agregado por dispositivo y muestra resultados en un dashboard web.

Repositorio GitHub: https://github.com/dafermen/netwatch-lite

La documentacion para programadores esta en docs/developer-guide.md. Ese archivo explica clases, metodos, servicios, endpoints, frontend y flujos internos.

Backend

ASP.NET Core minimal API en .NET 8. Expone endpoints para configuracion, temas, ejecuciones progresivas, recarga JSON y consultas de dispositivos.

Monitor

Usa Ping.SendPingAsync, TcpClient.ConnectAsync, Task.WhenAll y SemaphoreSlim para concurrencia controlada.

UI

HTML, Bootstrap 5, FontAwesome y JavaScript. Incluye resumen, facilities, categorias, filtros, busqueda, configuracion, temas, controles de ejecucion y layout responsive.

Portable

Se publica como win-x64 self-contained. Los archivos runtime config.json, regions.json, perfiles en regions/*.json y themes.json quedan junto a NetWatch-Lite.exe y no deben versionarse.

WebView2

Proyecto Windows en src/NetWatchLite.Wallboard.WebView2. Usa controles WebView2 nativos para paginas que bloquean iframes.

Flujo De Ejecucion

  1. La aplicacion inicia en Program.cs.
  2. JsonRegionProfileRepository administra perfiles independientes por support group dentro de una region configurable.
  3. JsonDeviceRepository.ReloadAsync carga y normaliza el JSON de la region activa.
  4. La UI llama GET /api/monitor/stream para ejecutar un full check progresivo.
  5. El modo automatico ejecuta un full check segun settings.intervalSeconds.
  6. NetworkMonitorService.CheckAllDevicesAsync revisa dispositivos habilitados en paralelo.
  7. Se calcula Healthy, Degraded o Down.
  8. El backend devuelve resultados con facility/categoria y genera metricas del dashboard.
  9. La UI agrupa primero por facility y luego por categoria, evitando ambiguedad cuando dos sedes usan nombres iguales.

Configuracion JSON

En desarrollo Data/config.json, Data/regions.json y Data/regions/*.json son locales e ignorados por Git. El ejemplo seguro versionado vive en Data/config.sample.json. Si no existen perfiles, la aplicacion crea un perfil Support Team A desde el config local cuando esta disponible y un perfil protegido Demo desde el sample.

El archivo themes.json tambien es runtime e ignorado por Git. Guarda templates de color para el GUI y se crea automaticamente con el tema NetWatch Default si no existe.

{
  "settings": {
    "intervalSeconds": 15,
    "timeoutMs": 1000,
    "maxParallelChecks": 50,
    "retryCount": 0,
    "retryDelayMs": 250
  },
  "devices": [
    {
      "name": "Web Server",
      "ip": "192.168.4.10",
      "hostname": "web-server.local",
      "useHostnameForPing": true,
      "websiteUrl": "https://example.local/status",
      "facility": "Miami Warehouse",
      "category": "Servers",
      "enabled": true,
      "checks": [
        { "type": "ping" },
        { "type": "tcp", "port": 80 },
        { "type": "tcp", "port": 443 }
      ]
    }
  ]
}
CampoDescripcion
intervalSecondsIntervalo, en segundos, usado por Auto Refresh para repetir el full check.
timeoutMsTimeout de ping y TCP en milisegundos.
maxParallelChecksLimite global de checks concurrentes.
retryCountReintentos adicionales despues de un ping o TCP fallido.
retryDelayMsPausa, en milisegundos, entre reintentos.
useHostnameForPingPreferencia por dispositivo. Cuando esta activo, el ping usa hostname si existe; cuando esta apagado usa ip.
hostnameNombre DNS opcional para ping en redes donde la IP puede cambiar.
websiteUrlURL HTTP/HTTPS opcional que muestra un link para abrir la pagina asociada desde el dashboard.
facilitySede, bodega, sucursal o datacenter. El dashboard permite filtrar y ejecutar checks por facility. Si falta, se normaliza como Unassigned.
categoryGrupo visual dentro de cada facility.
enabledPermite conservar dispositivos sin monitorearlos.
checksLista de checks. Soporta ping y tcp.

Proyecto Wallboard Hermano

El modo NOC WebView2 vive ahora en un repositorio separado: netwatch-lite-wallboard. Esa separacion mantiene este dashboard web enfocado en monitoreo de red y permite evolucionar el Wallboard como ejecutable Windows independiente.

WebView2 carga cada panel como navegador nativo, no como iframe, por eso es el modo recomendado para paginas operativas que bloquean embedding en navegador.

Frontend

wwwroot/index.html define el layout compartido: sidebar hamburguesa, topbar, dashboard, pagina de configuracion, pagina de temas, metricas, busqueda, filtros y contenedor de resultados. El dashboard inicia en modo manual por defecto. Cuando hay problemas aparece Run Failed para repetir solo los dispositivos fallidos, y cada fila con problema muestra Run junto al timestamp para repetir solo ese dispositivo.

El dashboard muestra botones de facility para enfocar una sede y habilitar Run Facility. En vista general, las tablas se agrupan por facility y luego por categoria, por lo que dos equipos con el mismo nombre en sedes distintas se ven como registros diferentes.

La pagina /regions permite crear, copiar, renombrar, activar y eliminar perfiles JSON independientes. La pagina /config trabaja sobre la region activa y agrupa los dispositivos por facility y categoria, con grupos colapsados por defecto para facilitar la edicion de inventarios grandes. El modo Bulk Edit muestra una tabla estilo hoja de calculo para actualizar campos comunes y guardar una fila a la vez; incluye filtros por facility/categoria y separadores visuales para evitar listas masivas dificiles de leer. Las acciones de agregar, copiar, actualizar y eliminar dispositivos guardan inmediatamente en el JSON activo, y el boton Save Settings guarda ajustes generales como intervalo, timeout, reintentos, pausa entre reintentos y concurrencia maxima. Export JSON descarga la configuracion activa e Import JSON valida un archivo antes de reemplazar esa configuracion.

La pagina /themes permite crear, copiar, renombrar, activar, borrar, resetear y guardar templates de color en themes.json. El nombre de un tema nuevo, copiado o renombrado se captura en modal, y los colores editables incluyen el sidebar, superficies, estados, categorias, headers colapsables de Configuration, Auto Refresh ON, Auto Refresh OFF y el boton principal de ejecucion.

El sidebar tambien incluye /manual con un manual de usuario integrado y /about con informacion del proyecto, su caracter libre y notas operativas.

wwwroot/app.js contiene funciones JSDoc para:

  • Consumir /api/monitor/stream para pintar resultados conforme termina cada dispositivo.
  • Renderizar metricas, facilities, categorias, filas, badges de estado, puertos y links opcionales de websiteUrl.
  • Contraer y expandir grupos de facility y categoria para navegar inventarios grandes; al completar un full check, los grupos se contraen y quedan en verde, naranja o rojo segun la salud final.
  • Manejar modo manual por defecto, auto refresh ON/OFF y el boton principal Run All Facilities/Run Facility.
  • Administrar dispositivos y checks desde la ruta /config.
  • Administrar templates de color desde la ruta /themes.
  • Filtrar por texto, facility, categoria, online, offline y problemas.

Crear Portable Windows

Comando recomendado:

dotnet publish NetWatch.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish/win-x64-v0.6.0

Resultado esperado:

publish/win-x64-v0.6.0/
├── NetWatch-Lite.exe
├── config.sample.json
├── appsettings.json
├── wwwroot/
└── runtime dependencies...

Crear ZIP en macOS:

cd publish/win-x64-v0.6.0
zip -r ../../releases/NetWatch-Lite-win-x64-portable-2026-06-19-v0.6.0-support-groups-bulk-edit.zip .

Uso en Windows:

  1. Descomprimir el ZIP.
  2. Editar config.json en la misma carpeta de NetWatch-Lite.exe o usar la pagina /config; si no existe, la aplicacion lo crea al iniciar.
  3. Editar temas desde /themes; si themes.json no existe, la aplicacion lo crea al iniciar.
  4. Ejecutar NetWatch-Lite.exe.
  5. Abrir la URL que muestra la consola.

Notas Operativas

  • El archivo config.json puede recargarse desde el boton Reload JSON en Configuracion o administrarse desde /config.
  • El archivo themes.json se administra desde /themes y guarda el tema activo y los templates de color.
  • Si config.json no existe, se crea automaticamente con un check de ping a 127.0.0.1.
  • Si themes.json no existe, se crea automaticamente con NetWatch Default.
  • Import JSON rechaza archivos vacios, archivos que no terminan en .json, archivos mayores de 5 MB, JSON invalido y configuraciones que no pasen validacion.
  • La aplicacion inicia en modo manual; el auto refresh solo empieza cuando el operador activa el boton y repite el full check segun settings.intervalSeconds.
  • Los botones de facility permiten enfocar y ejecutar una sede especifica cuando existen cientos de dispositivos.
  • Los grupos de facility y categoria se contraen al finalizar un recorrido y muestran barras verdes, naranjas o rojas segun el estado.
  • La barra de progreso del monitoreo se muestra solo mientras corre un full check.
  • En pantallas pequenas, los controles se apilan y las tablas anchas usan scroll horizontal para conservar legibilidad.
  • Run All Facilities y Run Facility no permiten ejecuciones solapadas; si una ya corre, el backend responde HTTP 409.
  • JSON corrupto o invalido se reporta por API/UI para poder corregir la configuracion sin un cierre silencioso.
  • Errores de lectura o escritura de configuracion se devuelven como respuestas controladas para mostrarlos en Configuracion.
  • Si falla un Run de grupo durante streaming, el dashboard conserva los resultados anteriores y muestra el error en la linea de estado.
  • Si falla un full check sin resultados previos estables, la UI muestra un panel de error en el dashboard.
  • Para redes grandes, ajustar maxParallelChecks segun capacidad de red y equipo.
  • El ping puede requerir permisos o reglas de firewall dependiendo del sistema operativo y la red.
  • Los checks TCP tratan timeouts, rechazos, destinos invalidos y fallos de socket como puertos no disponibles; no validan el protocolo de aplicacion.

Modelo De Seguridad

NetWatch Lite esta disenado como una herramienta operacional interna. La version actual no incluye autenticacion, roles de usuario ni autorizacion por permisos dentro de la aplicacion; por eso debe ejecutarse en una estacion o servidor interno confiable, o detras de controles existentes como VPN, firewall, autenticacion de reverse proxy o controles de acceso de Windows.

  • Los archivos runtime Data/config.json, Data/regions.json, Data/regions/*.json y Data/themes.json estan ignorados por Git.
  • El repositorio solo debe incluir Data/config.sample.json con datos genericos.
  • El publish excluye perfiles runtime para evitar que el portable incluya inventario operacional real.
  • Import JSON valida extension, tamano maximo, JSON valido y estructura de configuracion antes de reemplazar datos activos.
  • Los guardados se validan en backend antes de escribir archivos y crean backups locales.
  • Las ejecuciones de monitoreo evitan solapamiento y reportan errores controlados en API/UI.
  • Direcciones IP, hostnames, facilities, support groups y perfiles JSON deben tratarse como informacion operacional interna.
